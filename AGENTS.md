# DUSEMA AI Project Instructions

- Balance business utility, architecture simplicity, and practical learning for AI Engineering, Generative AI Engineering, and Agentic AI Engineering. Explain the problem, design choice, trade-offs, key code paths, verification steps, and interview takeaways in Spanish. Write code, technical documentation, and commits in English.
- Follow the approved [discovery baseline](docs/DISCOVERY.md), [release roadmap](docs/ROADMAP.md), [security policy](docs/SECURITY.md), and ADRs under `docs/adr/`. Work in small, verifiable increments. Obtain project-owner approval before substantial architectural changes and before implementing later-release scope early.
- Use deterministic code for business rules, authorization, money, and posting. Use AI for candidate extraction or other approved advisory work. Treat documents and model outputs as untrusted input. Keep synthetic data in development and evaluation. Use explicit permissions, deterministic validation, and human approval for critical operations.
- Keep credentials out of version control and logs. The proposed monthly model-call ceiling is USD 10. Obtain explicit authorization before making paid model calls or provisioning cloud services. CI and routine tests must work without paid API keys.
- Consult current official documentation for version-sensitive claims. For library and platform questions, use Context7 first when available. Resolve the project by name and query the relevant version and concept. Use indexed source for exact behavior when available. If Context7 is unavailable, use Exa when configured or consult the official sources directly. These tools are development aids and are outside the product and CI dependencies.
- Use the locked development environment and run the relevant tests and quality checks. Report only observed results and identify checks that could not run. Keep behavior, tests, and public documentation synchronized. Apply the Definition of Done in `docs/DISCOVERY.md`.
